# Make followup order proposals idempotent

Each proposed order has a deterministic proposal ID derived from its strategy sleeve, instrument, signal and trading dates, action, and position identity. Repeated followup runs preserve that identity, confirmed execution events reference it, and changed terms for an existing proposal are surfaced as conflicts rather than overwritten. An unfilled entry blocks a different entry for the same sleeve until it is filled or explicitly cancelled. An outstanding GTC stop retains its original identity across later sessions; its own confirmed partial fills project the broker-active remaining quantity without mutating the submission, while other changed price or quantity terms conflict until that proposal is cancelled. A replacement then receives a session-specific identity. Expiry waits for cancellation, and a GTC stop left outstanding after another exit closes the position blocks the sleeve's next entry. Day target and expiry instructions otherwise receive session-specific identities tied to the same position. This prevents repeated report generation from becoming repeated manual orders.
